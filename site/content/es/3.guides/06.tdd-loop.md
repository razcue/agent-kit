En los proyectos SDD + TDD la skill `tdd` guía cada cambio de comportamiento:

1. **Lista los casos**: los escenarios que se implementan (cada uno ya etiquetado con una categoría ZOMBIES) y luego casos unitarios extra con ZOMBIES. Escribe primero los nombres de los tests, el más simple primero.
2. **Rojo**: escribe un test, ejecútalo y confirma que falla por el motivo esperado (la aserción, no un error de import).
3. **Verde**: el cambio más pequeño que lo hace pasar.
4. **Refactor**: solo en verde, y vuelve a ejecutar.
5. **Siguiente caso.** Un arreglo de bug empieza con un test que lo reproduce.

```bash [Terminal]
npx @razcue/agent-kit tdd status        # archivos de lógica cambiados y sus tests (✗ no test = pendiente)
npx @razcue/agent-kit tdd run           # solo los tests relacionados con tus cambios; --all para toda la suite
```

`agent-kit tdd run` imprime el código de salida y los fallos; el log completo va a `.agent-kit/runs/`. Los nombres de los tests se leen como reglas y empiezan con el id del escenario que prueban. Nunca debilites, saltes ni borres un test para llegar a verde.
