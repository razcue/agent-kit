::steps
### Renueva el checklist

```bash [Terminal]
npx @razcue/agent-kit qa sync
```

### Prepara los datos

En proyectos con Supabase, reinicia los datos de prueba en la base de QA: `purge.sql` y luego `seed.sql` (ver [Datos de prueba](/es/guides/test-data)).

### Empieza una pasada

```bash [Terminal]
npx @razcue/agent-kit qa run --env staging
```

Esto crea `work/qa/runs/<hoy>.md` con todos los escenarios sin marcar, agrupados por capacidad. Una segunda pasada el mismo día recibe `-2`.

### Prueba y registra

Para cada escenario, sigue su Given / When / Then y escribe el **Result** (`pass`, `fail`, `blocked`, `n/a`) y una **Note**. ¿Prefieres el navegador? Abre `work/qa/checklist.html`, registra ahí y usa **Export run** para guardarlo en `work/qa/runs/`.

### Revisa

```bash [Terminal]
npx @razcue/agent-kit qa status
```

Los fallos se vuelven arreglos de vía rápida o cambios. Los escenarios marcados **re-check** cambiaron desde la última vez que pasaron; los **never run** nunca se probaron.
::
