`agent-kit.json` guarda las respuestas de la instalación. Cámbialas volviendo a ejecutar `agent-kit init`.

| Campo | Qué es | Por defecto |
|---|---|---|
| `name` | Nombre del proyecto (kebab-case). | nombre de la carpeta |
| `kind` | Tipo de proyecto: lo que generó `init`.<br>`monorepo` — plantilla web + app + docs con Nuxt + Supabase<br>`site` — un sitio Nuxt sencillo con páginas en Markdown, lo más fácil<br>`existing` — añade la capa del agente al código de esta carpeta<br>`blank` — solo la capa del agente, sin plantilla, desde cero | se pregunta |
| `apps` | Apps del monorepo (`web`, `app`, `docs`); vacío en los demás tipos.<br>`web` — sitio público (Nuxt, prerenderizado)<br>`app` — solución principal (SPA Nuxt + BFF + Supabase)<br>`docs` — sitio de ayuda / wiki (Docus) | `web,app,docs` |
| `stack` | Skill de convenciones del stack instalada en `.claude/skills/`.<br>`none` — sin skill de convenciones<br>`nuxt-supabase` — skill stack-nuxt-supabase (páginas, rutas BFF, migraciones, RPCs)<br>`nuxt-content-site` — skill stack-nuxt-content-site (páginas Markdown, estilos, build) | según el tipo |
| `technicalLevel` | Cómo te habla el agente.<br>`technical` — lenguaje conciso de desarrollador<br>`non-technical` — lenguaje sencillo; el agente toma las decisiones técnicas | `technical` |
| `language` | Idioma de respuesta del agente.<br>`en` — English<br>`es` — Español | `en` |
| `methodology` | SDD, o SDD + TDD (tests primero, exigidos por preflight).<br>`sdd-tdd` — spec primero, luego tests antes del código; preflight bloquea la lógica sin tests<br>`sdd` — spec primero; cada escenario verificado por un test o una comprobación | `sdd-tdd` |
| `commitConvention` | Conventional Commits revisados por commitlint, o mensajes libres.<br>`conventional` — type(scope): subject, revisado por commitlint y un hook de git<br>`none` — sin revisión de mensajes | `conventional` |
| `gitFlow` | Qué puede hacer el agente con git (lo aplica un hook).<br>`pr` — el agente nunca hace commit ni push en main<br>`trunk` — commits en main; sin force-push ni reset duro<br>`read-only` — el agente nunca cambia git; tú ejecutas git | `pr` |
| `mainBranch` | La rama principal (de producción): se detecta desde git al instalar (el HEAD de origin, o la única rama main / master / trunk / production / prod), se pregunta si no hay certeza; `upgrade` comprueba que exista. Preflight compara contra ella; el git guard la protege. | detectada, si no `main` |
| `testIgnore` | Rutas sin tests unitarios (manejadores de rutas delgados). | `apps/*/server/api/` en el monorepo |
| `testCommand` | Comando que ejecuta los tests, si no es el de siempre. | — |
| `contextBudget` | Tokens por sesión a partir de los cuales falla `doctor`. | `8000` |
| `supabaseMcp` | Ref del proyecto de Supabase para el servidor MCP de solo lectura en `.mcp.json`. | — |
| `qa.checklist` | Genera `work/qa/checklist.md` desde las specs vivas. | `true` |
| `qa.testData` | Scripts seed / purge de Supabase (solo proyectos con Supabase). | `true` con Supabase |
| `qa.testPrefix` | Marca con la que empieza cada fila de prueba. | `TEST_` |
| `qa.testDataDir` | Dónde viven los scripts de datos de prueba. | `supabase/test-data` |
| `kitVersion` | Versión del kit que escribió la instalación por última vez (activa el aviso de actualización). | la escribe init |
