En cada sesión solo se carga la descripción de cada skill; el cuerpo se carga cuando una tarea lo necesita. Las descripciones originales están en inglés: son las que lee Claude Code.

## adopt

Se usa ANTES de editar AGENTS.md / CLAUDE.md para reducirlos o bajar el contexto por sesión, y al pasar un proyecto existente a agent-kit: medir, mapear cada sección, mover los procedimientos a skills, las reglas de un área a archivos CLAUDE.md por carpeta y los hechos a .knowledge/, una sección a la vez. Se activa con: "adopt agent-kit", "slim AGENTS.md", "too many tokens", contexto por encima del presupuesto.

- **Origen**: plugin (todo proyecto)

## commit

Se usa ANTES de cualquier commit de git: cuando el usuario dice "commit", "commit message", "save this work", o se termina una spec / feature. Ejecuta preflight, revisa lo que entra, escribe un mensaje Conventional Commit (type(scope) subject, en inglés), lo valida con commitlint y hace el commit dentro del flujo de git del proyecto (o le da al usuario el comando exacto cuando git es de solo lectura).

- **Origen**: plugin (todo proyecto)

## decide

Registra una decisión de arquitectura o diseño (ADR) en el ámbito correcto: las del proyecto en .knowledge/decisions y las de varios proyectos en meta global. Se usa cuando se toma o se consulta una decisión con impacto duradero ("let's go with…", "we decided…", "should we use X or Y" una vez resuelto), o cuando se reemplaza una decisión anterior.

- **Origen**: plugin (todo proyecto)

## feature

Se usa ANTES de cualquier cambio pequeño de código: un arreglo, un ajuste, un añadido pequeño de interfaz (≤ 3 archivos, sin cambios de esquema, permisos ni dinero). Abre un archivo en work/features con objetivo, tareas y evidencia para que el trabajo sobreviva a los reinicios de sesión. Se activa con: "fix", "tweak", "small change", "change X to Y", "add X to the page". El trabajo más grande o arriesgado → skill `spec`.

- **Origen**: plugin (todo proyecto)

## knowledge

Lee y escribe la base de conocimiento por ámbitos: conceptos del negocio, hechos de los entornos, convenciones del stack, reglas de UI/UX, reglas meta entre proyectos. Se usa antes de trabajar en un área desconocida ("how do we…", "what is…") y cuando aparece un hecho, regla o convención duradera que una sesión futura debe saber ("remember…", "from now on…", "the rule is…").

- **Origen**: plugin (todo proyecto)

## preflight

Revisión de la rama actual antes de fusionar: migraciones por aplicar o editadas por error, variables de entorno nuevas, dependencias nuevas, posibles secretos, restos de depuración, permisos a anon/authenticated, scripts sin documentar y (SDD + TDD) lógica cambiada sin test. Se usa antes de un PR o una fusión, al cerrar una spec / feature, o cuando el usuario pregunta "what do I need to do to ship this?".

- **Origen**: plugin (todo proyecto)

## retro

Retrospectiva que convierte la experiencia en configuración duradera: las correcciones repetidas se vuelven conocimiento o reglas de hooks, los scripts desechables reutilizados se promueven y lo que no se usa se poda. Se usa cuando el usuario dice "retro", "what did we learn", "improve the setup", al terminar una spec, o una vez al mes más o menos.

- **Origen**: plugin (todo proyecto)

## scripts

Decide, encuentra, construye, documenta, prueba y ejecuta scripts para que se reutilicen en lugar de reescribirse. Se usa antes de escribir CUALQUIER script o programa auxiliar (ayudantes de tests, comprobaciones de datos, generadores, "write a script that…"), antes de volver a crear un script improvisado anterior y al conservar o documentar scripts. Busca primero en los scripts y las skills existentes.

- **Origen**: plugin (todo proyecto)

## spec

Carril guiado por specs (SDD × TDD) para trabajo grande o arriesgado: un módulo o conjunto de páginas nuevo, cambios de esquema / RPC, permisos, dinero, cualquier cosa de más de ~3 archivos. Abre un cambio (propuesta + specs delta), consigue la aprobación, implementa con tests primero, verifica cada escenario y lo fusiona en las specs vivas. Se usa cuando el usuario dice "spec", "plan this", "new module", o el trabajo supera la vía rápida.

- **Origen**: plugin (todo proyecto)
- **Archivos**: `references/notation.md`, `templates/delta.md`, `templates/plan.md`, `templates/proposal.md`, `templates/tasks.md`

## start

Arranque guiado de un proyecto nuevo o de un trabajo grande nuevo: hace preguntas sencillas (qué, para quién, qué páginas o funciones, aspecto, contenido) y convierte las respuestas en la primera spec. Se usa cuando el usuario dice "start", "I want to build…", "new site/app/project", o cuando work/ está vacío y el pedido es abierto.

- **Origen**: plugin (todo proyecto)

## tdd

Se usa ANTES de escribir o cambiar lógica cuando el usuario pide TDD, "test first" o tests, o el método del proyecto es SDD + TDD. Rojo → verde → refactor, un comportamiento a la vez, casos de test elegidos con ZOMBIES, tests relacionados ejecutados de forma compacta con tdd.mjs. También cuando preflight informa lógica sin tests.

- **Origen**: plugin (todo proyecto)

## stack-nuxt-content-site

Se usa ANTES de añadir o cambiar páginas, textos, navegación, colores, imágenes o componentes en este sitio Nuxt Content (content/*.md, app/, nuxt.config.ts). Convenciones para páginas Markdown, frontmatter, orden, tokens de estilo, componentes MDC, SEO y el build estático.

- **Origen**: plantilla (se instala en `.claude/skills/` de los proyectos con ese stack)

## stack-nuxt-supabase

Se usa ANTES de añadir o cambiar páginas, componentes, rutas de servidor (apps/*/server/api), autenticación, esquemas Zod, migraciones SQL, RPCs o datos de prueba en el monorepo Nuxt 4 + shadcn-vue + Tailwind v4 + Supabase (apps/web, apps/app, apps/docs, packages/ui, packages/shared). Convenciones y patrones, con detalles en references/.

- **Origen**: plantilla (se instala en `.claude/skills/` de los proyectos con ese stack)
- **Archivos**: `references/bff.md`, `references/migrations.md`, `references/monorepo.md`, `references/test-data.md`, `references/ui.md`
