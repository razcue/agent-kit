La ruta de la carpeta de scripts está en el contexto de sesión; la mayoría también son comandos `agent-kit`.

## changes

Lo que cambió desde la rama base: commiteado + preparado + sin preparar + sin seguimiento. Lo comparten preflight.mjs y tdd.mjs. Git de solo lectura.

## checkpoint

Hook de Stop: tras cada turno (síncrono: los hooks asíncronos se pierden cuando termina una ejecución headless) guarda el estado del trabajo para que la siguiente sesión lo retome: rama, archivos cambiados, trabajo activo. En silencio; nunca falla.

## commit

Ayudas de Conventional Commits para los agentes.

```bash
node commit.mjs draft [--staged]        changed files → suggested scope(s) and type
node commit.mjs check "<message>"       validate: project commitlint if installed,
node commit.mjs check --file <path>     else the built-in rules below (exit 1 = invalid)
```

## config

Rutas y configuración compartidas por los scripts del plugin y la CLI de agent-kit.

## context

Estima el contexto que se carga en CADA sesión de Claude Code de un proyecto (cadena CLAUDE.md + imports, índice de memoria, contexto de sesión de agent-kit, descripciones de skills) y encuentra las skills que Claude Code no ve. ~4 caracteres por token.

```bash
node context.mjs [dir] [--budget 8000]      exit 1 over budget
node context.mjs [dir] --sections            cost of every heading in the CLAUDE.md chain
```

## git-guard

Hook de PreToolUse(Bash): bloquea los comandos de git que prohíbe el flujo de git del proyecto. La salida 2 bloquea la llamada y muestra stderr a Claude. En silencio fuera de los proyectos agent-kit.

## git-rules

Qué comandos de git nunca cambian un repositorio: datos para el git guard (git-guard.mjs). Subcomandos que nunca cambian el repositorio, sean cuales sean sus argumentos.

## knowledge

Base de conocimiento: un concepto por archivo Markdown con frontmatter, agrupados en ámbitos y enlazados con [[name]]. Este script hace el trabajo determinista (índice, búsqueda, validación) para que los agentes solo gasten tokens en las entradas que abren.

```bash
node knowledge.mjs paths
node knowledge.mjs find <terms...> [--body]
node knowledge.mjs related <name>       the entry, what it links to, what links to it
node knowledge.mjs index [--global]
node knowledge.mjs check [--global]
```

## preflight

Lista de comprobación antes de fusionar a partir del diff entre la base de fusión y el árbol de trabajo (commiteado + preparado + sin preparar + sin seguimiento). Git de solo lectura.

```bash
node preflight.mjs [base-branch]      exit 1 when a violation is found
```

## qa

La dimensión de QA: un checklist generado desde las specs vivas (un ítem por escenario), pasadas de QA con fecha que registran resultados, y el mapa de escenarios a fixtures de datos de prueba (`-- @fixture <ids…> @tag` en seed.sql).

```bash
node qa.mjs sync [--check]   regenerate work/qa/checklist.md + checklist.html (--check: exit 1 if stale)
node qa.mjs run              start work/qa/runs/<today>.md with every scenario unticked
node qa.mjs status           latest result per scenario (pass / fail / blocked / n/a / re-check / never run)
node qa.mjs gaps             scenarios without a fixture; fixtures naming unknown scenarios (exit 1)
```

## run

Ejecuta un comando y devuelve un resultado compacto para el agente: código de salida, tiempo, las líneas que importan (fallos, errores) y el final. La salida completa va a un archivo de log, así que una ejecución larga cuesta unas decenas de líneas de contexto, no miles.

## script-nudge

Hook de PostToolUse(Write): cuando el agente escribe un script donde se perdería (fuera del proyecto, en la raíz del proyecto o en una carpeta tmp), le recuerda la skill `scripts` para que el script se encuentre y se reutilice la próxima vez.

## scripts

Registro de scripts: busca, ejecuta, prueba, genera y documenta los scripts que escriben agentes y usuarios, para que se reutilicen en lugar de reconstruirse. Un script se documenta con líneas `@clave: valor` en sus primeras 40 líneas (cualquier estilo de comentario): @name @summary @usage (obligatorios: summary, usage) · @tags [a, b] · @test archivo

```bash
node scripts.mjs find <words...>          scripts (project, scratch, library) + skills
node scripts.mjs list
node scripts.mjs run <name|path> [--lines N] [-- args...]
node scripts.mjs test [name]
node scripts.mjs new <area>/<name>.<ext> --summary "…" [--usage "…"] [--scratch|--library]
node scripts.mjs index                    regenerate scripts/README.md
node scripts.mjs check                    undocumented, duplicate, missing tests
```

## session-start

Hook de SessionStart: inyecta el perfil del proyecto (tono, idioma, flujo de git, método, carriles de trabajo), un índice compacto del conocimiento y el índice de scripts. En silencio fuera de los proyectos agent-kit.

## specs

Specs vivas (work/specs/<capability>/spec.md) y las specs delta de los cambios (work/changes/NNN-slug/specs/<capability>.md). Notación: requisitos EARS (`### cap.R1 — name`), escenarios Given/When/Then etiquetados con una categoría ZOMBIES (`#### cap.R1.S1 — name @boundary`). Los ids nunca se reutilizan.

```bash
node specs.mjs lint [cap|NNN]          notation + id checks (exit 1 on errors)
node specs.mjs next <cap|cap.Rn>       next free requirement / scenario id
node specs.mjs merge <NNN>             apply a change's deltas to the living specs
node specs.mjs trace [NNN|cap]         scenario → tests (id in the test name) or ✅ rows
node specs.mjs list                    capabilities with requirement and scenario counts
```

## tdd

Soporte de TDD: qué archivos de lógica cambiados no tienen test, y una ejecución compacta solo de los tests relacionados con los cambios actuales.

```bash
node tdd.mjs status [base]
node tdd.mjs run [test files...] [--all] [--base <branch>] [--lines N]
```

## usage

Señales de uso para una retro: qué se ejecutó y falló, scripts nunca usados, scripts desechables por promover o borrar, conocimiento que nadie enlaza, estado del trabajo.

```bash
node usage.mjs [--days 30]
```

## work

Seguimiento del trabajo: features de vía rápida (work/features/) y cambios (work/changes/NNN-slug/: propuesta, specs delta, plan, tareas), su estado y próxima tarea, y la trazabilidad (escenario → test o comprobación verificada). Las specs vivas (work/specs/<capability>/spec.md) las maneja specs.mjs.

```bash
node work.mjs status              active work with progress and next task
node work.mjs board               regenerate work/BOARD.md
node work.mjs trace [NNN]         scenarios (or legacy AC-n) → tests or ✅ checks
node work.mjs new feature|change <slug> [--title "…"]   next number + files from the templates
```
