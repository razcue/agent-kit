## Requisitos

- **Node.js ≥ 20.11** y npm.
- **Claude Code** (CLI, app de escritorio o extensión del IDE).
- Se recomienda git: el git guard y preflight trabajan sobre el repositorio.

## Preparar un proyecto

::steps
### Ejecuta `init`

```bash [Terminal]
npx @razcue/agent-kit init my-project
```

En un repositorio existente, ejecútalo dentro de la carpeta: `cd my-repo && npx @razcue/agent-kit init`. Tu `AGENTS.md` se conserva y recibe un bloque gestionado.

### Responde las preguntas

| Pregunta | Opciones |
|---|---|
| Tipo de proyecto | **Monorepo de app nuevo** (web + app + docs con Nuxt + Supabase) · **Sitio de contenido nuevo** (un sitio Nuxt con páginas en Markdown) · **Proyecto existente** (solo la capa del agente) · **Proyecto en blanco** (solo la capa del agente, sin plantilla) |
| Apps (monorepo) | `web`, `app`, `docs` |
| Nivel técnico | Técnico (lenguaje conciso de desarrollador) · No técnico (lenguaje sencillo; el agente toma las decisiones técnicas) |
| Idioma de respuesta del agente | English · Español |
| Método de desarrollo | SDD + TDD (tests primero, obligatorio) · SDD (cada escenario verificado por un test o una comprobación) |
| Mensajes de commit | Conventional Commits (commitlint + hook de git) · Libres |
| Flujo de git del agente | Ramas + pull requests · Trunk · Solo lectura (tú ejecutas git) |
| Rama principal (de producción) | Se detecta desde git: el HEAD de origin, o la única rama `main` / `master` / `trunk` / `production` / `prod`; solo se pregunta si no hay certeza (`--main <rama>`) |
| Skill de convenciones del stack (existente / en blanco) | Ninguna · Nuxt + Supabase · Sitio Nuxt Content |
| Checklist de QA | Generado desde las specs vivas en `work/qa/` (por defecto sí) |
| Datos de prueba de Supabase (proyectos con Supabase) | Scripts seed / purge en `supabase/test-data/` (por defecto sí) |
| Ref del proyecto de Supabase (opcional) | Añade a `.mcp.json` un servidor MCP de Supabase de solo lectura, limitado al proyecto |

`init` muestra el plan y pregunta antes de escribir. Cada archivo que cambia se respalda en `.agent-kit/backups/`.

### Abre Claude Code en el proyecto

```bash [Terminal]
cd my-project && npm install && claude
```

Confía en la carpeta. `.claude/settings.json` declara el marketplace de agent-kit y activa `agent-kit@agent-kit`, así que Claude Code ofrece instalar el plugin: acepta. Si no lo hace:

```text [Claude Code]
/plugin marketplace add razcue/agent-kit
/plugin install agent-kit@agent-kit
```

### Comprueba la instalación

```bash [Terminal]
npx @razcue/agent-kit doctor
```

`agent-kit doctor` revisa las respuestas, el bloque de AGENTS.md, el plugin, los índices de conocimiento y de scripts, el presupuesto de contexto y la skill de stack. `--fix` regenera todo lo generado (índices, el tablero de trabajo, el checklist de QA).
::

## Instalación no interactiva

Cada pregunta tiene un flag; `--yes` toma los valores por defecto para el resto:

```bash [Terminal]
npx @razcue/agent-kit init shop --yes --kind monorepo --apps web,app,docs \
  --level technical --lang en --method sdd-tdd --commits conventional --git pr \
  --qa-checklist true --test-data true --test-prefix TEST_
```

Todos los flags están en la [referencia de la CLI](/es/reference/cli#agent-kit-init).

## Cambiar una respuesta después

Vuelve a ejecutar `init` con el nuevo valor; solo toca la capa del agente:

```bash [Terminal]
npx @razcue/agent-kit init --git read-only --yes
```

## Hacer escribible el conocimiento global (mantenedores del kit)

Los proyectos leen el conocimiento global que trae el plugin. Para escribir entradas globales desde tu máquina, registra un clon del kit:

```bash [Terminal]
git clone https://github.com/razcue/agent-kit.git && cd agent-kit
npx @razcue/agent-kit setup
```

`agent-kit setup` escribe `~/.config/agent-kit/config.json`; desde entonces los agentes guardan el conocimiento global y las propuestas de mejora en ese clon.
